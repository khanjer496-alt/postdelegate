# PostDelegate server-confirmed acquisition and activation

CEO assignment source: `Shared/launch-review/growth/postdelegate-funnel-baseline.md`. This app PR and the companion Pulse PR form one measurement queue, after security releases R3/R4. Release Engineer owns staging/deployment. No source data, campaigns, customer messages, charges or live account settings are changed here.

## Boundaries and evidence

A new internal `MeasurementEvent` ledger records server-confirmed outcomes with stable keys; upserts increment duplicate observations without changing original time or evidence. No public client endpoint can insert a registration/trial/schedule/publication/payment milestone. Ledger failures log a sanitized `measurement_write_failed` message and do not fail signup, posting or a payment webhook. Therefore continuous completeness must be qualified/reconciled before a funnel is used: reported totals are **observed durable milestone rows**, not proof that no event was missed during an outage. No historical approval or paid conversion is inferred/backfilled.

- Signup attempts are syntactically valid server-observed register submissions; they are not registration success. Browser UUID headers dedupe delivery retries; legacy clients without them get server-generated request IDs. Authentication validation failures before the route executes are outside this attempt denominator.
- Registration requires a newly created owner workspace and an activated owner. Local email signups count after activation; provider/activation-free signups count after accepted creation. Existing-user login, member invites and manual super-admin grants do not create registration events.
- Eligibility means a verified new owner workspace granted trial eligibility. Enrollment is separate: confirmed provider `trialing` state, actual trial-start date and trial end. App `isTrailing` alone is never used as enrollment evidence.
- Channel connected is recorded after persistence and after page selection when applicable. Incomplete/off/deleted channels and providers hidden from general availability do not qualify; preview permission does not make a provider publicly available.
- First draft is a stored draft. First qualifying schedule needs an authenticated human save or human/client approval, accepted `QUEUE` state, a future publish date and an available connected channel. The ledger snapshots `humanApproval`, `acceptedPublishAt`, evidence type and a hash of the post reference. Agent/API/internal saves alone never qualify. The accepted schedule event remains separate from provider publication.
- Publication needs persisted `PUBLISHED` plus provider `releaseId`; it dedupes by post + receipt. It is not claimed from a timer or a schedule click.
- Stripe `invoice.payment_succeeded` records non-zero paid **subscription** invoices only. Paid conversion additionally requires an eligible workspace and an applied active/past_due entitlement for the same actual Stripe subscription. The app's plan `identifier` is not the Stripe subscription ID; transient provider-state context now passes the latter for this join. Context fields are not persisted into the Subscription row. $0 invoices, unmatched payments, test traffic and all lifetime grants are excluded from qualified paid/revenue counts. Stripe Ops independently reconciles the live aggregates and qualifies staging webhook/replay behavior.

## Consent-aware first touch

Pulse signs source/medium/campaign/term/content, entry page, device, test class, random nonce and a 24-hour expiry. There is no email, name, IP or visitor ID in the token. Marketing carries it as `pd_touch` in the signup URL. Signup sends it directly to the server; no new cookie, localStorage or sessionStorage is written. Bad/missing/expired tokens remain unmatched/unknown and cannot affect auth, billing or redirects.

For Google/GitHub/Apple/generic OAuth, the initiating request sends that token to the server. A ten-minute `MeasurementHandoff` maps a hash of the existing OAuth state nonce to it, without putting acquisition data in the OAuth cookie or weakening the existing exact state-cookie check. After that check succeeds the continuation is returned to the form in memory. Wallet/Farcaster auth changes remain with the R4 owner; those paths currently remain unmatched if they cannot carry the URL context.

One signed touch can match one new workspace (`touchHash` uniqueness); reuse stays unmatched. Acquisition tokens can expire during a slow signup, so unmatched counts are a real output, not relabeled as direct traffic. DNT/GPC/tracker blocking remain unmatched. Aggregate match means a valid permitted first-touch receipt, not verified cross-day human identity. Source/campaign dimension visitor counts must not be treated as additive unique people.

Release Engineer must install a shared, newly generated 32+ byte `PULSE_HANDOFF_SECRET` on Pulse and app through the secret flow, and set `MEASUREMENT_RELEASE` to the deployed revision. Neither is installed by this PR. Existing consent-based `pulse_vid` behavior is not expanded.

## Export contract

Super-admin only: `GET /admin/measurement?from=<ISO instant>&to=<ISO instant>`. Use explicit offsets/UTC; instants are half-open `[from,to)` with a maximum 93-day window. App server-local timezone does not redefine them. Exported daily dates and trial-week starts (Monday) are Asia/Dubai, UTC+4. Today may be excluded by choosing a complete-window `to`.

Daily workspace rows contain the binding baseline fields:

`date, source, campaign, entry_page, device, internal_or_test, lifetime, eligible_visitor_ids, signup_attempts, confirmed_new_owner_workspaces, eligible_trial_workspaces, confirmed_trial_starts, channel_connected_workspaces, first_draft_workspaces, approved_accepted_future_schedule_workspaces, provider_confirmed_publications, paid_subscription_workspaces, nonzero_subscription_payments, entitlement_applied_workspaces, revenue_minor, currency`.

`eligible_visitor_ids:null` is unavailable in the workspace table. The companion Pulse `/api/measurement` provides the separate visitor-unit table. Unknown dimensions stay `unknown`; no email, account/user/workspace/post/invoice identifiers or person-level rows are exported. Currency rows remain separate; never sum currencies or overlapping workspace dimensions. Internal/test and lifetime diagnostic classes remain visible and must be excluded from commercial denominators. Diagnostic raw payments remain in the internal ledger; unmatched/test/lifetime payments never become qualified revenue.

Cohorts expose trial-start week, eligibility class, eligible trials, fully observed 48h trials, first qualifying schedules within 48h, fully observed trial-end+7d trials, qualified conversions within that window and later conversions. Cohorts require observed instrumentation through maturity and use the current read's `as_of`; a recent trial is not silently put in a mature denominator. Subscription eligibility and schedules before the requested window are read internally for joins; no identifier is returned. More than 100,000 source events fails closed with an unavailable status and asks for a smaller window.

Reconciliation includes recorded total server milestones, valid event identities, matched eligible workspace, matched permitted acquisition, unmatched, duplicate observations, delayed (>5 minutes), internal/lifetime exclusions, unmatched subscription payments and observed join completeness. Coverage states source release, first durable instrumentation time, retention, 24-hour attribution window, consent/ingestion limits and unavailable historical backfill. The `days` calendar marks pre-instrumentation dates Unavailable and the first date Partial; absence there is never zero demand.

Raw ledgers are retained during ordinary operation. The existing explicitly confirmed permanent workspace-erasure flow deletes that workspace’s measurement rows; its schema-decision test covers the new model. OAuth continuations expire after ten minutes and only expired temporary continuations are pruned on subsequent handoff reads/writes. No erasure or source-data deletion was executed by Builder. Privacy/retention review remains a release gate.

6. Verify the two baseline complete 30-day windows and seven-day detail; pre-install dates stay Unavailable. Keep real paid qualification read-only with Stripe Ops; test financial webhook delivery only in the dedicated PostDelegate Staging sandbox.
7. Rollback app and Pulse together to prior approved images if any privacy/auth/entitlement/posting check fails. Stop new instrumentation before reverting. Preserve the new ledgers for review; do not drop them or delete raw evidence as part of rollback. Re-review schema diff before any later removal.
