# Bring-your-own AI key — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Each workspace stores its own OpenAI API key, encrypted, and every AI feature uses that key. No code path can bill a platform key.

**Architecture:** A new `AiCredential` Prisma model with repository, service, DTO and controller, following the `third-party` / `webhooks` layering. `AiCredentialService` is the only source of OpenAI keys and clients. The permission gate for `Sections.AI` and `/user/self.aiAvailable` become "this workspace has a credential". Every module-level OpenAI client is removed, and each call site asks the service for the org's client. The frontend gets a Settings → AI tab.

**Tech Stack:** NestJS, Prisma 6 (`db push`), `openai` v6, `@ai-sdk/openai` (`createOpenAI`), `@langchain/openai`, Mastra, CopilotKit, React (Vite), SWR with `useFetch`, Tailwind 3, Jest.

**Spec:** `docs/superpowers/specs/2026-10-31-byo-ai-key-design.md`. Read it first. Its "Decisions after the builder check" section overrides the earlier sections where they disagree.

## Global Constraints

- Follow the repo `CLAUDE.md`: DTO >> Controller >> Service >> Repository; logic in `libraries/nestjs-libraries`; Prisma only; pnpm only; lint only from the root.
- Never edit Temporal workflow files under `apps/orchestrator/src/workflows`, and never change any activity's parameters.
- No runtime code may read `process.env.OPENAI_API_KEY`. At the end, `git grep -n "OPENAI_API_KEY" -- apps libraries` may only show non-runtime mentions (comments, `.env.example`, tests asserting it is ignored).
- The decrypted key is never returned by any endpoint, logged, put into a Mastra `requestContext`, or passed as a Temporal activity argument.
- Missing-key error text (exact): `Add your OpenAI key in Settings → AI`
- Invalid-key error text (exact): `OpenAI rejected this key. Check it's an active API key with access to models.`
- Masked key format: the first 3 characters, then `…`, then the last 4 (for example `sk-…a9F2`).
- Encryption: `AuthService.fixedEncryption` / `AuthService.fixedDecryption` from `@gitroom/helpers/auth/auth.service`.
- Frontend: one SWR hook per call, through `useFetch`; native components only; no `--color-custom*`; strings via `t('key', 'Default')`.
- Commit after each task, ending with the trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A workspace removes its key while an autopost or clipping job is running. The job must stop cleanly, with no retry storm and no AI-less post published. (Task 4 test.)
2. `OPENAI_API_KEY` is set on the server, but the workspace has no key. AI must stay unavailable and calls must fail with the missing-key error. (Tasks 2 and 3 tests.)
3. A team member with the USER role calls `POST/DELETE /ai-credentials`. They must get 403. (Task 1 controller test.)
4. A key that's saved and then rotated or revoked at OpenAI makes a call fail. The OpenAI 401 error must not echo the key into our logs or response. (Task 3: wrap the client errors in the call sites already covered by `generationError` or by plain `BadRequestException` messages.)
5. MCP `ask_postdelegate` is called with no web request context. The model must resolve the org via `getAuth()`, or throw the missing-key error. (Task 3 test.)
